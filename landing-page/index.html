What it does

01 It reads the repository, not just the patch

Every PR gets a detached git worktree of the actual branch. Claude opens the files, follows the call sites, and reads your CLAUDE.md and conventions.

02 Nothing is sent unseen

Every control that sends a prompt opens one confirmation showing the exact prompt, with a note box to aim it and an Edit control to rewrite it. Anything that writes to the pull request is marked before you click.

03 Findings come with evidence

Not "consider refactoring this". A finding names the file and line, states the input that produces the wrong result, and cites what it checked. Disagree, and Challenge runs an adversarial re-check that is appended, never overwritten.

04 A mixed batch gets mixed criteria

Pick Auto detect and the tool finds the pull requests first, proposes a profile and a note for each, and shows you every row to correct before a single line is reviewed.

05 Azure DevOps and GitHub

The host is read from the repo's git remote, so a machine with both az and gh is never ambiguous. One session can hold pull requests from both.

06 It stays yours

Sessions, findings and the full event log live in the repo you reviewed. No extra account, no analytics. Every session is a real Claude Code session: resume it with claude --resume <id>.
